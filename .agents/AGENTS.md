# Agent Rules

* **No Comments:** Absolutely no code comments or docstrings allowed; enforce self-documenting code.
* **File Granularity:** Keep classes under 150 lines.
* **Explicit Interfaces:** Always define both `@Local` and `@Remote` interfaces for EJBs; avoid no-interface views.
* **Comprehensive Test-As-We-Go:** At the end of every implementation phase involving new entities or business logic, agents MUST proactively write **BOTH** Unit Tests (using pure JUnit 5 with Hibernate Validator for Entity constraints) and Integration Tests (Arquillian for EJBs). Do not skip Unit Tests.
* **No CLI Maven:** Agents must not run `mvn` in the terminal (rely on user's IDE).
* **Testing Framework Constraint:** Do NOT use Mockito for testing. Use pure JUnit 5 for Unit Tests and Arquillian for Integration Tests.
* **Arquillian Test Data Cleanup:** Always include an `@AfterEach` method in Arquillian Integration Tests to delete any dummy entities persisted during the test setup, preventing live database pollution.
* **Immediate Test Reporting:** Immediately after creating or modifying any test, the agent MUST update `Test_Report.md`. This is a mandatory step that cannot be deferred. The report MUST maintain two separate tables: one for "Unit Tests" and one for "Integration Tests", and all tests must be logged into their respective tables.
* **Database Context:** The project uses PostgreSQL. When writing SQL queries, database instructions, or troubleshooting persistence issues, always assume PostgreSQL syntax and behaviors.
* **Arquillian ShrinkWrap Completeness:** When creating or modifying Entity classes, EJBs, or Interceptors, you MUST proactively search for and update the `@Deployment` (`ShrinkWrap.create()`) methods in ALL existing Arquillian Integration tests to include the new classes via `.addClasses()`. **This explicitly includes any new Enums, DTOs, or Custom Exceptions that are added as fields or referenced.** Missing transitive JPA dependencies will cause `DeploymentException` and `ClassNotFoundException`.
* **Arquillian Remote Workflow (Chicken & Egg):** The project uses `wildfly-arquillian-container-remote`. Tests require an active WildFly server, but starting the server requires building the EAR, which fails if tests aren't passing. **Agents must explicitly advise the user to turn OFF Maven tests (skipTests) during standard builds to break this cycle.** Tests should only be run manually via the IDE *after* the server has successfully started with the deployed EAR.
* **Flaky Test Prevention (Simulators & Timers):** When writing Arquillian assertions that test EJB Timers interacting with simulated components (which may use random chance or cause immediate state jumps), assertions must account for instantaneous state transitions to prevent flaky tests (e.g., using `assertTrue` with OR logic rather than strictly asserting an intermediate step).
* **Action Verification Before Reporting:** Before claiming a task/phase is complete or updating reports (like `Test_Report.md`), agents MUST verify that the necessary code files have actually been created or modified (by ensuring the tool calls were successfully executed). Do not write reports based purely on planned code.
